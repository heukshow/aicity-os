## 매일 다른 사람들의 글에서 활동

- 관련 원문/대화 10–15개를 읽는다.
- 적합한 글에 좋아요 5–10개, 구체적인 공개 댓글 3–5개를 목표로 한다. 이는 보장된 실적이 아니다.
- 일일 새 좋아요 10개, 먼저 남기는 공개 댓글 5개를 넘기지 않는다. 기존 실행 기록을 읽고 중복을 막는다. 적합한 글이 없으면 미달로 기록한다.
- 관련 답글을 확인하고 필요한 공개 응답을 남긴다. 가능하면 하루 두 번의 짧은 활동으로 나눈다.
- 게시물의 전체 맥락과 필요한 연속 글·기존 답글을 읽고, 구체적인 보완 의견이나 질문을 남긴다. 같은 칭찬·인사 복제, 맞팔 유도, 무관한 링크 홍보, 가짜 경험이나 사람인 척하는 서술을 사용하지 않는다.
- AI 업무 활용, 영업 후속 조치, CRM, SaaS 평가, 작은 사업의 반복 업무 개선을 우선한다.

## 검증된 PC Remote 경로

사용자가 설치된 PC Threads 및 기존 자동 로그인 사용을 명시적으로 승인했다. Remote Desktop Commander의 Windows UI Automation으로 실제 계정, 본문 입력, 게시, 공개 URL을 확인했다. 클라우드 CUA에 네이티브 앱이 없다는 이유로 Remote PC 조작도 불가능하다고 판단하지 않는다.

1. 승인된 온라인 PC의 Threads 창을 찾고 실제 UI의 주소가 `https://www.threads.com/`인지 확인한다. 글을 열면 창 제목에서 Threads가 빠질 수 있다. 기존 창 핸들을 유지하되 매번 출처를 확인한다. 저장된 계정 쿠키·토큰·비밀번호를 읽지 않는다.
2. 공개 글을 읽는다. 실제 공개 링크는 timestamp Hyperlink의 `ValuePattern.Current.Value`로 읽을 수 있다. 링크를 얻기 위해 공유 버튼을 누르지 않는다.
3. 좋아요는 해당 글에 속한 현재 버튼을 확인한 뒤 누르고, `좋아요 취소` 상태로 바뀐 것을 읽어 완료를 확인한다.
4. 댓글은 해당 공개 글의 `답글` 버튼으로 연다. 창의 `답글` 표제, 작성 계정 `showm_ic`, 해당 원글, 정확한 편집 칸을 확인한다. DM/수신인 화면이면 진행하지 않는다.
5. Chromium 편집 칸은 ValuePattern.SetValue만으로 글이 입력되지 않을 수 있다. 검증한 비밀번호가 아닌 편집 칸에 포커스를 맞추고 공개 원고를 유니코드 붙여넣기한 뒤 TextPattern으로 원문 전체를 읽어 일치 여부를 확인한다. 다른 창에 키를 보내지 않는다.
6. 원고 일치와 대상 계정을 확인한 후 공개 `게시`를 누른다. 시간 초과 시 현재 글부터 확인하고 중복 게시하지 않는다. 게시 후 실제 본문·작성 계정·공개 URL을 확인해 기록한다.
7. 사용자가 직접 조작 중인 화면에 임의 키 입력을 하지 않는다. 읽기와 기록은 가능한 한 포커스를 바꾸지 않고 수행한다. PC가 오프라인이거나 UI가 확인되지 않으면 실제 미수행으로 남긴다.

## DM·공유 금지

사용자는 주소 확인 중 공유 기능이 수신인 제안/DM으로 이어질 수 있음을 지적했다. 실제 수신인 선택·메시지 입력·전송 명령은 없었다. 이후 개별 DM, 수신인 추천/선택, 공유 버튼은 사용하지 않는다. 공개 댓글과 하트만 이 활동 범위에 포함한다.

## 타인 글에서 사이트 개선으로 연결

원문 URL, 관측일, 구체적인 질문/불편/평가 기준, 해당 COSHUMA 페이지, 현재 구현과의 차이, 개선 가설, 담당 팀을 기록한다. 이미 충족한 내용은 중복 편집하지 않는다. 실제 갭이 있으면 기존 승인 안에서 작은 원본 수정→필수 검증→배포→실서비스 확인을 진행한다. 원문의 성과 수치는 검증 전 사실로 옮기지 않고, 글을 복제하지 않는다.

첫 관측의 고정 양식·반복 작업 아이디어는 현재 Claap 3-call 체크리스트에 동일 5개 필드, 원문 대조, 누락/수정 구분, 코칭 우선순위 안내로 이미 반영되어 있었다. 따라서 이 건은 현재 소스 수정 0개이며, 추가 개선 완료로 집계하지 않는다.
